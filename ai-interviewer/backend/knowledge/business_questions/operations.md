# 运营 题库

面向 C 端用户准备运营岗（用户运营 / 内容运营 / 活动运营 / 社群运营）面试的检索种子题。题目以"请结合你做过的真实项目/活动"为主轴，鼓励候选人回到自己简历经历展开。每组题目包含 base + 2-3 个渐进式 follow-up，配套 2-3 条评分要点。

难度标签：
- `intro` 开场或背景题
- `standard` 主战场，需要讲清"目标 / 动作 / 数据 / 复盘"
- `deep_probe` 深挖追问，要求量化或暴露真实决策过程

## 维度：用户增长 (user_growth)

### 1. 拉新策略选择
- **base** [intro]：你做过的拉新动作里，最有代表性的一个是什么？目标用户、渠道、核心钩子分别是什么？
- **follow-up** [standard]：选这个钩子之前，你考虑过哪些备选？为什么这个赢了？
- **follow-up** [deep_probe]：拉来的新用户和你预期的目标用户匹配度如何？有没有出现"量上来了但都不是核心用户"的情况？
- **评分要点**：钩子设计是否结合用户动机和成本；能否区分"流量来了"和"对的人来了"；是否量化匹配度（留存 / 转化 / LTV）。

### 2. 留存提升
- **base** [standard]：选一个你做过留存提升的项目，讲讲当时留存曲线长什么样、你定位的关键流失点在哪、做了什么动作。
- **follow-up** [standard]：动作上线后留存曲线怎么变？变化量里有多少能归因到你的动作？
- **follow-up** [deep_probe]：归因不清晰的部分你怎么处理？有没有过事后发现"留存涨了其实是季节性"的情况？
- **评分要点**：是否真的看过分群/分日的留存曲线；归因方式是否结合 A/B 或对照组；能否承认归因边界。

### 3. 转化漏斗优化
- **base** [standard]：你拆过转化漏斗吗？挑一个你做过的，讲讲漏斗每一步的流失率和你重点优化了哪一步、为什么选这一步。
- **follow-up** [deep_probe]：优化某一步之后，下游环节的流失率有没有变化？怎么判断不是"挤压效应"（前面通过率高了但后面卡住）？
- **评分要点**：能否说出每一步具体流失率（不是定性"高/低"）；优化选点是否结合"杠杆 × 难度"；能否警惕局部最优带来全局损失。

### 4. 增长瓶颈识别
- **base** [standard]：你过往的项目里，遇到过增长停滞的阶段吗？当时你是怎么诊断瓶颈在哪的？
- **follow-up** [deep_probe]：诊断结果有没有和你最初的直觉不一样？最后选择突破哪一边？
- **评分要点**：诊断是否系统（数据 / 用户访谈 / 渠道分析）；能否承认直觉偏差；选择突破点是否结合 ROI。

## 维度：内容运营 (content_operations)

### 5. 内容选题
- **base** [intro]：你做过内容运营吗？最近一次重要的选题是怎么定的？为什么是这个、不是另一个？
- **follow-up** [standard]：选题之后内容效果怎么样？哪些数据让你觉得这个选题做对了或者没做对？
- **follow-up** [deep_probe]：复盘下选题决策——如果重新做一次，你会怎么改进选题流程？
- **评分要点**：选题决策是否结合用户兴趣 / 业务目标 / 时机；是否有可复用的选题机制（不是每次靠灵感）。

### 6. 内容生产链路
- **base** [standard]：你管过内容生产流程吗？从选题到上线大概几步、每步的产出标准、卡点在哪？
- **follow-up** [deep_probe]：流程里你最近一次优化是哪一步？优化前后的产出效率或质量怎么变？
- **评分要点**：流程描述是否具体可操作；优化是否量化（出稿周期 / 一次过审率 / 阅读完成率）。

### 7. 爆款复盘
- **base** [standard]：你做过的内容里有没有爆款？讲一个，重点说当时数据为什么跑出来——是选题、人群、时机、还是分发？
- **follow-up** [deep_probe]：爆款经验怎么沉淀？后续有没有复制成功？复制不成功的部分是因为什么？
- **评分要点**：归因是否区分必然因素和偶然因素；能否承认"爆款不可批量复制"但仍提取可复用要素。

### 8. 内容质量与运营效率的平衡
- **base** [standard]：在生产节奏紧的时候，你怎么平衡"内容质量"和"产出量"？
- **follow-up** [deep_probe]：你团队里有没有过为了赶量牺牲质量、最后吃亏的经历？怎么调整的？
- **评分要点**：是否真有量化的质量门槛（不是"我们都很认真"）；调整是否落到流程或激励机制而非口头要求。

## 维度：数据分析 (data_analysis)

### 9. 用数据找问题
- **base** [intro]：你接到一个"我们最近 GMV 跌了 / 留存掉了"的诊断任务，你会怎么开始？
- **follow-up** [standard]：实际做过的一次类似诊断里，你最后定位到的根本原因是什么？这个原因第一时间不容易发现，是因为什么？
- **follow-up** [deep_probe]：定位到原因之后，你做的动作和原因之间的因果关系怎么验证？
- **评分要点**：诊断思路是否结构化（拆维度 → 分人群 → 看时间窗）；能否区分相关和因果。

### 10. 关键指标与北极星
- **base** [standard]：你的产品/活动的北极星指标是什么？为什么是这个？
- **follow-up** [deep_probe]：这个北极星有没有过被钻空子的情况？你怎么发现、怎么修补？
- **评分要点**：北极星是否真的代表用户价值（不是 vanity metric）；能否设计反作弊辅助指标。

### 11. 假设驱动的实验
- **base** [standard]：你做过最严谨的一次 A/B 测试是哪个？讲讲假设、流量分配、结果。
- **follow-up** [deep_probe]：实验结果显著但你最后没采用上线方案，有过吗？为什么？
- **评分要点**：实验设计是否考虑显著性 / 样本量 / 时间窗口；能否区分"统计显著"和"业务有意义"。

### 12. 跨工具数据贯通
- **base** [standard]：你在过往工作里，数据散落在多个工具（CRM / BI / 用户行为埋点 / 内容平台）的情况是怎么处理的？
- **follow-up** [deep_probe]：有过为了拉通数据做过工程性投入吗？这个投入值不值？
- **评分要点**：能否兼顾"快速分析"和"基础设施投入"；ROI 判断是否结合频率 × 价值。

## 维度：活动执行 (campaign_execution)

### 13. 活动从 0 到 1
- **base** [intro]：你独立或者主导跑过一个活动吗？讲讲从立项到上线再到复盘的关键节点。
- **follow-up** [standard]：活动里你最纠结的一个决策是什么？最后基于什么做了决定？
- **follow-up** [deep_probe]：复盘下整个活动，最大的执行风险出现在哪一步？是怎么暴露的？
- **评分要点**：流程描述是否具体到时间节点和负责人；纠结点是否真的是关键决策（而非琐碎细节）；能否还原风险暴露过程。

### 14. 资源协调
- **base** [standard]：活动需要研发、设计、客服等多方协作时，你怎么排期、怎么对齐节奏？
- **follow-up** [deep_probe]：有过因为某一方延期把整个活动节奏拖乱的经历吗？怎么处理的？
- **评分要点**：协调机制是否有明确节奏（站会/check-in/缓冲）；处理延期是否同时管理风险和关系。

### 15. 突发问题处理
- **base** [standard]：活动上线后出现过什么意料之外的问题？你怎么处理的？
- **follow-up** [deep_probe]：那次的处理之后，下一次活动你的预案设计有什么变化？
- **评分要点**：现场处理是否有"先止血再溯源"的层次感；学习是否真正写进 SOP。

### 16. 效果量化与归因
- **base** [standard]：活动效果你怎么量化？除了 GMV 或者参与人数，你还看哪些指标？
- **follow-up** [deep_probe]：活动结束后多久你认为可以下"成功 / 失败"的判断？为什么这个时间点？
- **评分要点**：指标体系是否覆盖广度（参与）+ 深度（转化）+ 长期（留存）；时间窗口判断是否结合用户决策周期。

## 维度：流程优化 (process_optimization)

### 17. 识别低效流程
- **base** [intro]：你团队里有没有"大家都觉得低效但没人改"的流程？你做过推动改的尝试吗？
- **follow-up** [standard]：推动改流程时，最难的不是设计新流程，而是让大家用起来。你怎么处理这个？
- **follow-up** [deep_probe]：有没有过新流程上线一段时间后又退回老流程的？怎么避免这种回退？
- **评分要点**：能否区分"流程问题"和"执行问题"；推动是否结合人 / 工具 / 激励三方面。

### 18. 自动化与人工的平衡
- **base** [standard]：你做过哪些"原来人工做、后来变成系统化"的事？怎么决定哪些值得自动化？
- **follow-up** [deep_probe]：自动化之后有没有出现过新的问题（比如 SOP 变僵化、人不再关注异常）？
- **评分要点**：自动化决策是否结合频次 × 错误成本；能否预见自动化的副作用。

### 19. 跨团队 SOP
- **base** [standard]：你写过给其他团队用的 SOP 吗？怎么保证他们真的按 SOP 执行？
- **follow-up** [deep_probe]：SOP 没被严格执行的情况下，你倾向于改 SOP 还是推动执行？为什么？
- **评分要点**：能否分辨"SOP 设计有问题"和"执行没到位"；处理方式是否兼顾灵活性和一致性。

### 20. 复盘机制
- **base** [standard]：你团队的复盘机制是什么？如何保证复盘出真问题、不流于形式？
- **follow-up** [deep_probe]：复盘里发现的问题有多少最后真的被改掉？怎么追踪改了没？
- **评分要点**：复盘是否有结构（事实 / 原因 / 改进 / 责任人 / 时间）；改进项是否有闭环跟踪。

### 21. 经验沉淀
- **base** [standard]：你做完一个项目，怎么把经验沉淀给后面的人？是文档、模板、还是别的？
- **follow-up** [deep_probe]：你沉淀的内容真的被后人用过吗？怎么知道的？
- **评分要点**：沉淀方式是否结合复用场景（不是为写而写）；能否检验沉淀真的产生杠杆。

## 通用追问触发器

- 候选人说"我们活动 GMV / 拉新 / 转化提升了 X%" → 追问"基线是什么？大盘自然增长扣掉了吗？活动期之外的对比期是怎么选的？"
- 候选人说"我们做了一次 A/B" → 追问"流量怎么分？样本量？显著性？置信区间？有没有 novelty effect？"
- 候选人说"我推动了某个流程上线" → 追问"上线后真的有人按这个流程走吗？怎么验证的？"
- 候选人说"用户很喜欢我们的内容" → 追问"用什么数据看到的？分享 / 复访 / 评论质量哪个更重要？"
- 候选人说"我们靠裂变拉新很成功" → 追问"裂变拉来的用户和自然流量在留存上有差异吗？这个 ROI 怎么算？"
